### R2 — Roundup reel content vs label divergence (PLAUSIBLE, accepted v1)
The roundup rung ships ONE remaining theme's produced reel (`remaining[0]`) but stamps it
with a merged multi-theme attribution + "Roundup of takes" label. So the reel the user
watches is a single theme's story while the credit line lists several themes' handles. This
is the documented v1 simplification (spec §3: further themes "roll into a SINGLE roundup
reel"; composite multi-element theme imagery is explicitly v2). Not a faked
theme-of-the-day (it is honestly labeled a lower rung); flagged for product sign-off. If
rejected, either produce a true multi-theme roundup reel or narrow the roundup attribution
to its carrier theme.

### R3 — FK resilience when the produce wiring lands (future integration risk)
`daily_feeds.feed_story_id` is `NOT NULL REFERENCES stories(story_id)` and `write_daily_feed`
inserts the per-user feed as one batch. When R1's produce path lands, a candidate whose
`reel_story_id` is not persisted in `stories` (e.g. dropped by the verification gate) would
fail the ENTIRE per-user insert — the same risk class as the existing `source_stories` path.
The producer (R1) must drop candidates whose reel story is not persisted before building
`XThemeReelCandidate`s. No live risk today (no production caller passes candidates).
